# ПРОЕКТ-СВАРКА — диагностический аудит сайта

Дата: 2026-09-14

## Статус

Сайт НЕ считать боевым до исправления архитектурных конфликтов shared UI.

## Обнаруженные проблемы

### 1. Анимация логотипа

Статус: КРИТИЧЕСКИЙ риск.

Причина:
- В `site-header.js` логотип собирается как HTML-элемент:
  `img src="assets/logo-mark.svg"`.
- Дополнительная вспышка создаётся отдельным HTML-слоем:
  `.site-header__flash`.
- Это не гарантирует привязку к координатам SVG.
- При разных размерах логотипа, масштабировании и разных контейнерах искра может смещаться.

Правильное решение:
- анимация искры должна находиться внутри самого SVG `logo-mark.svg`;
- координаты должны быть в системе viewBox SVG;
- внешний CSS-слой `.site-header__flash` удалить.

---

### 2. Разделение сайта на разные версии

Статус: КРИТИЧЕСКИЙ риск.

Причина:
- `create.html` имеет отдельную логику нормализации через `replaceCreateFooter()`.
- Остальные страницы проходят через другую ветку.
- Получается несколько сценариев сборки DOM.

Последствие:
- разные цвета шапки;
- разные размеры бренда;
- разные состояния fixed-header;
- разное поведение кнопки «Наверх».

Правильное решение:
- одна точка инициализации UI;
- один header;
- один footer;
- одна CSS-система.

---

### 3. MutationObserver

Статус: ОПАСНЫЙ участок.

Причина:
- `MutationObserver` вызывает `syncSharedUi()` после каждого изменения DOM.
- Внутри вызываются функции, которые сами изменяют DOM.

Риск:
- циклические обновления;
- повторные вставки элементов;
- визуальные скачки.

Необходимо:
- добавить защитный debounce;
- отключать observer во время собственных изменений;
- после изменения выполнять один sync.

---

### 4. Кнопка «Наверх»

Статус: требуется проверка.

Текущая логика создаёт кнопку динамически.

Риск:
- разные страницы могут иметь разные контейнеры прокрутки;
- DC-контейнер может перехватывать scroll.

Необходимо:
- единый scroll target;
- одна кнопка в body;
- один обработчик.

---

### 5. Мобильное меню

Статус: требуется проверка.

Возможная причина:
- CSS открытия `.is-open` находится вне проверенного общего модуля.
- JS меняет класс, но без гарантированных стилей меню может не раскрыться.

Необходимо проверить:
- наличие CSS для `.site-header__links.is-open`;
- z-index;
- overflow;
- position.

---

### 6. Бренд ПРОЕКТ-СВАРКА

Статус: частично исправлено.

В `site-header.js` бренд задан единым текстом:
`ПРОЕКТ-СВАРКА`.

Но:
- футер и шапка используют общий HTML только через JS;
- старые локальные стили страниц могут переопределять шрифт.

Необходимо удалить старые правила `.header`, `.brand`, `.logo-title`.

---

## Главная причина текущих поломок

Не проблема отдельных кнопок или шрифтов.

Корень проблемы:

Сайт имеет смешанную архитектуру:

- статический HTML;
- динамический общий UI;
- старые стили страниц;
- отдельные исправления для create.html.

Это создаёт конфликт источников правды.

---

## План восстановления

1. Зафиксировать текущую рабочую версию.
2. Убрать специальные ветки для create.html.
3. Сделать единый `site-shell.js`:
   - header;
   - footer;
   - logo;
   - mobile menu;
   - scroll button.
4. Перенести анимацию полностью внутрь SVG.
5. Удалить старые стили шапок.
6. Проверить каждую страницу:
   - Главная;
   - create.html;
   - Калькулятор;
   - Лофт-мебель;
   - Документация;
   - Прайс.
7. Проверить мобильную версию.

## Итоговый вывод

Предыдущие исправления были частичными. Они закрывали отдельные симптомы, но не устраняли конфликт архитектуры. Текущий этап требует не новых костылей, а возврата к одному общему модулю сайта.
